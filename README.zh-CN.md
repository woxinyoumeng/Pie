# PiCode

**面向编码代理的原生 macOS 界面 —— 支持 [Pi](https://pi.dev/)、Oh My Pi、Claude Code、Codex、OpenCode 与 DeepSeek。**

PiCode 让每种代理保持为运行时本体,并为它提供一个专注桌面的界面,用于长时间运行的编码会话。项目与对话近在手边,代理的活动始终可读;需要时,文件、差异与命令输出会在对话旁边打开。

![PiCode 展示项目侧栏、编码对话与源文件检查器](assets/screenshot.png)

> [!IMPORTANT]
> PiCode 是客户端,不是 Pi 的分支或替代品。它启动你已经安装好的代理可执行文件(对 Pi 而言是 `pi --mode rpc`),沿用它们各自的服务商与原生会话文件,并且凭据始终由各代理自行掌管。

## 主要特性

- **多代理程序** —— 在一个应用里运行 Pi、Oh My Pi、Claude Code、Codex、OpenCode 或 DeepSeek Harness。按项目分别选择代理程序、服务商与模型;安装、更新与登录都可以在「设置」里完成。
- **原生 Mac 体验** —— SwiftUI 界面、系统浅色与深色外观、熟悉的菜单与键盘快捷键,以及支持 VoiceOver 的控件。
- **对话优先的工作区** —— 流式 Markdown 回复、归组的工具活动、推理指示、重试、压缩事件与错误都集中在一份对话记录里,并支持消息编辑与「跳到最新」气泡。
- **项目与会话** —— 图标栏加侧栏:搜索、置顶、重命名、恢复、克隆、派生、导出与后台删除。长列表显示最近十条,并提供「显示更多」。
- **在对话旁审阅** —— 无需离开对话即可查看文件、编辑、差异、读取与命令输出;工作区菜单可打开终端面板、访达或 VS Code。
- **完整的运行控制** —— 可逐层深入的「代理程序 / 服务商 / 模型」选择器、分级推理控制、上下文标签、附件、插话、排队跟进,以及停止。
- **代理程序原生定制** —— 命令、技能、提示词模板、扩展、自定义服务商与包都从代理程序自身发现,不再维护另一份目录。
- **本地优先的状态** —— 每个代理程序掌管自己的消息与会话;PiCode 只保存界面状态,例如最近项目、置顶、草稿与布局偏好。

## 支持的代理程序

| 代理程序 | 命令 | 传输方式 | 说明 |
| --- | --- | --- | --- |
| **Pi** | `pi` | `pi --mode rpc`(JSONL) | 功能完整:会话树、派生、扩展对话框 |
| **Oh My Pi** | `omp` | Pi 系 RPC | 会话索引与部分命令/事件名与 Pi 不同 |
| **Claude Code** | `claude` | `claude --print`,stream-json | 工具以内容块形式流式返回;会话树、派生与扩展对话框仅 Pi 支持 |
| **Codex** | `codex` | `codex exec --json` | 助手文本按条目到达,而非逐 token;跟进会恢复同一线程 |
| **OpenCode** | `opencode` | `opencode run --format json` | 复用 `opencode auth login` 配置的服务商;模型来自已安装目录 |
| **DeepSeek Harness** | `dsh` | 换行分隔的 JSON-RPC | 不支持逐 token 流;可列出已保存会话,但暂不支持恢复 |

各代理程序能力不同,PiCode 会隐藏某项代理程序无法兑现的控件。代理程序按项目选择;由于每个运行时都有自己的进程与会话存储,切换代理程序会开启新对话。会话如何被发现与恢复,见 [SESSION_STORAGE.zh-CN.md](SESSION_STORAGE.zh-CN.md)。

## 环境要求

- macOS 14 Sonoma 或更高版本
- 至少安装一种受支持的代理程序,并能在登录 shell 的 `PATH` 中找到(Pi 是参考实现)
- 支持 macOS 14 SDK 的 Xcode(从源码构建时需要)

PiCode 通过你的登录 shell 和常见安装位置查找每种代理程序。「设置 → 代理程序」会显示已安装的内容,提供安装命令(npm、bun、brew、curl)—— 只有你点击时才会通过登录 shell 执行 —— 并检查更新。任何东西都不会被自动安装或修改。

例如,你可以用下面任一命令安装 Pi:

```sh
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

```sh
curl -fsSL https://pi.dev/install.sh | sh
```

开始对话前,请先用代理程序自身的常规认证流程配置至少一个服务商(例如 `opencode auth login`,或登录 Claude Code / Codex)。当你明确要求时,PiCode 也可以在「设置」里管理 API 密钥凭据与自定义服务商;这些改动会写入代理程序文档化的配置文件,而不是 PiCode 的副本。

## 构建与运行

1. 用 Xcode 打开 `PiCode.xcodeproj`。
2. 选择 **PiCode** scheme,目标选择 **My Mac**。
3. 按 `⌘R` 构建并运行。
4. 选择 **新建对话**,选中一个项目文件夹,然后在新项目面板中选择代理程序、服务商与模型。若出现代理程序的信任提示,请先处理它。

PiCode 为每个活动会话启动一个代理进程,并以所选项目作为该进程的工作目录。

## 工作原理

```text
SwiftUI 视图
    ↕
PiCode 状态与服务
    ↕ 类型化命令与事件
AgentRuntime 适配器(Pi · Oh My Pi · Claude Code · Codex · OpenCode · DeepSeek)
    ↕ stdin/stdout JSON(RPC、stream-json 或 exec --json)
代理进程
    ↕
服务商 · 代理循环 · 工具 · 会话 · 扩展
```

职责边界是刻意划分的:

| 归属 | 数据与行为 |
| --- | --- |
| **代理程序** | 消息、代理状态、模型、思考等级、队列、压缩、重试、会话历史、扩展与认证 |
| **PiCode** | 最近项目与每个项目的代理程序选择、置顶、草稿、可重建的会话元数据目录、对话位置、窗口布局与界面偏好 |
| **Git** | 工作区状态与差异 |
| **代理程序 / 钥匙串** | 服务商密钥与 OAuth 令牌 |

这样终端会话与桌面会话保持兼容,也避免为代理程序数据制造第二个事实来源。`PiCode/Harness/Adapters` 中的每个适配器都把各自代理程序的线格式挡在应用其余部分之外。

## 扩展与包

对于 Pi 系代理程序,PiCode 支持 Pi 的 RPC 模式所暴露的扩展交互,包括命令、通知、状态、小组件,以及原生的选择、确认、输入与编辑器对话框。

有些扩展 API 需要 Pi 的终端界面,无法通过 RPC 复现,例如任意自定义 TUI 组件、页眉或页脚替换、自定义编辑器,以及 TUI 主题控制。PiCode 会保持会话可用、指出该兼容性限制,并在可行时让你转到终端继续。

Pi 的包与扩展可以以你的 macOS 账号权限执行任意代码。安装前请审阅其源码。PiCode 把包的安装与卸载交给你自己的 Pi 安装完成,因此图形界面与终端看到的是同一套环境。

## 安全与隐私

代理程序以启动它的用户权限在本地运行。项目信任决定是否加载项目本地的配置与可执行扩展;**它不是沙箱**,也不限制模型发起的常规工具调用。

PiCode 不要求自己的账号,也不会把代理程序的会话或凭据镜像到另一个数据库。诊断用的 RPC 载荷捕获默认关闭;在排查问题时启用后,内容也只保留在内存中,不会写入磁盘。

对于不受信任或无监督的工作,请使用容器或其他操作系统级隔离手段。

## 项目状态

PiCode 仍在积极开发中。首个正式版本的定义是:端到端的会话可靠性、忠实还原的 Pi 行为、安全的审阅流程,以及完整的键盘与辅助功能支持。

完整的产品规格、架构、兼容性边界、交付计划与完成标准见 [IMPLEMENTATION.zh-CN.md](IMPLEMENTATION.zh-CN.md)。

## 设计原则

1. **对话优先。** 当前任务及其状态占据窗口主体。
2. **渐进披露。** 常用控件保持可见;高级控件收进菜单、搜索与检查器。
3. **每一步代理动作都清晰可读。** 工具调用、输出、错误、重试、压缩、排队消息与文件变更都有明确状态。
4. **代理程序始终是权威。** PiCode 反映运行时的命令与事件,而不是另造一套与之竞争的状态。
5. **用清晰换取安全。** 应用展示工作目录与信任状态,但不会把信任说成沙箱。
6. **本地优先。** 会话与凭据留在 Pi 掌管的位置。
